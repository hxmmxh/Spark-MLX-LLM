# ViT 融合支持与测量说明

实现按 MLX 0.32.4、Apple M5 Pro（applegpu_g17s）和 Python 3.12 验证。NAX GEMM 读取 MLX 随包提供的私有 Metal 头文件。代码通过 MLX 编译 Metal kernel，不再构建本包的 C++ 扩展。

模型入口仅对单图、N>64、hidden=1152、intermediate=4304、16 个 D72 head、BF16 激活与参数、epsilon=1e-6 启用分段实现。多图、量化权重、其他设备、dtype 或维度使用原始路径。各段计算函数面向固定布局，模型入口负责通用分派。

投影去掉单核完成计数后，GEMM+残差与 LayerNorm 分开执行。LayerNorm 使用原始 MLX 路径，保持原来的归约与舍入。该变化增加一个逻辑 kernel 调用，同时去掉计数器初始化、原子发布与跨线程组内存栅栏；实际延迟通过同输入配对测量判断。

本轮比较固定同一套真实 BF16 权重和两张图像。仅比较源码已冻结且输出通过位级一致核对的实现。计时是主机墙钟，编译、预热、输入处理与数值核对均在计时外。完整塔只在最终输出处求值与同步，不通过单算子耗时相加推算整塔收益。

旧版投影和 C++ 桥接保存在研究目录的 projection-python-20261125-paired/source/projection_before 中，便于逐行审阅；运行身份、全部样本与资格标记在对应结果目录保存。

2026-11-25 的投影精简对比采用 projection-python-20261125-idle。该轮通过连续三个 CPU active <15%、GPU active <10% 的空闲样本准入，420 对采样全部通过活动检查，没有新增 swap-out。前一轮 projection-python-20261125-confirm 未通过空闲准入，3844 patch 的一组投影窗口出现竞争高 CPU 进程。原始记录仍保存在各自目录，耗时表采用通过空闲准入的一轮。两轮算法源码完全相同。

本轮完整塔中位耗时变化为 −1.82%～+0.43%。3844 patch 的两条路径分别为 220.24 和 221.19 ms，该档逐对耗时降幅的中位数为 0.008%。各路径耗时中位数的比值与逐对比值的中位数具有不同的统计口径。结果支持两版效率接近，不能据此认定整塔获得稳定加速。报告保留全部样本和两种统计。

此前 MLP 精简的独立确认记录为 mlp-direct-20261124-confirm，其基线来自提交 89ab4a0。该轮通过空闲准入，420 对全部通过活动检查，56 项数值核对位级一致。本轮投影对比的两侧均采用已精简的 MLP，未将历史 MLP 收益计入本次投影变化。

仓库清理同时移除了旧的 qkv_rope_backend="metal" 实验开关。视觉融合统一使用 block_backend="segmented"，通用原始计算和回退使用 block_backend="native"。本次清理没有修改 vit_fusion 中已测量的 Python/Metal 算法文件，历史耗时表仍对应原测量轮次。
